# async_websocket_client

[![CI](https://github.com/sigidagi/awc/actions/workflows/ci.yml/badge.svg)](https://github.com/sigidagi/awc/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)
[![Version](https://img.shields.io/github/v/tag/sigidagi/awc?sort=semver&label=version)](https://github.com/sigidagi/awc/tags)
[![C++20](https://img.shields.io/badge/C%2B%2B-20-blue.svg?logo=cplusplus)](https://en.cppreference.com/w/cpp/20)
[![Coverage](https://img.shields.io/badge/coverage-100%25-brightgreen.svg)](https://github.com/sigidagi/awc/actions/workflows/ci.yml)

A non-secure (`ws://`) WebSocket client written with C++20 coroutines on top of
`boost::asio::io_context` and Boost.Beast.

* **Coroutine API** – `co_await client.connect()`, `send()`, `receive()`, `close()`.
* **Automatic reconnect** with exponential back-off, optional attempt limit.
* **Ping/pong keep-alive** with pong timeout detection and RTT statistics.
* **`std::expected` based error handling** – no exceptions cross the API.
* **spdlog** logging through a replaceable logger.
* **GoogleTest** suite with an in-process misbehaving test server (100 % function,
  ~100 % line coverage of the library).
* clang-format / clang-tidy / lcov integration in CMake, CMake presets, and a
  summarising check script.

## Build

The quickest path uses the CMake presets (build trees go to `build/<preset>`):

```sh
cmake --workflow --preset dev        # configure + build + test (Debug)
cmake --workflow --preset ci         # same in Release with -Werror
cmake --workflow --preset clang      # Debug with Clang and -Werror
```

Individual steps:

```sh
cmake --preset dev && cmake --build --preset dev && ctest --preset dev
cmake --preset coverage && cmake --build --preset coverage   # HTML in build/coverage/coverage/index.html
cmake --preset tidy && cmake --build --preset tidy           # clang-tidy on every translation unit
cmake --build --preset format                                # clang-format -i on all sources
cmake --build --preset format-check                          # fails if anything is not formatted
```

| Preset | Purpose |
|--------|---------|
| `dev` | Debug build with tests and examples |
| `release` | Release build, warnings as errors |
| `clang` | Debug build with Clang, warnings as errors |
| `coverage` | `--coverage` instrumentation, `coverage` target runs tests + lcov |
| `tidy` | runs clang-tidy while compiling |

The presets set these CMake options, which can also be passed by hand:

| Option | Default | Effect |
|--------|---------|--------|
| `AWC_BUILD_TESTS` | ON | build the GoogleTest suite |
| `AWC_BUILD_EXAMPLES` | ON | build `examples/` |
| `AWC_ENABLE_COVERAGE` | OFF | instrument with `--coverage` and add the `coverage` target |
| `AWC_ENABLE_CLANG_TIDY` | OFF | run clang-tidy on every translation unit |
| `AWC_WARNINGS_AS_ERRORS` | OFF | `-Werror` |

## Usage

```cpp
#include "async_websocket_client/client.hpp"

asio::awaitable<void> talk(awc::WebSocketClient& client) {
    if (auto ok = co_await client.connect(); !ok) {
        spdlog::error("{}", ok.error().to_string());
        co_return;
    }
    co_await client.send_text("hello");
    if (auto reply = co_await client.receive()) {
        spdlog::info("got {}", reply->payload);
    }
    co_await client.close();
}

int main() {
    awc::ClientConfig config;
    config.url = "ws://127.0.0.1:9001/";
    config.ping_interval = std::chrono::seconds{15};
    config.reconnect.max_attempts = 10;

    asio::io_context ioc;
    awc::WebSocketClient client(ioc, config);
    asio::co_spawn(ioc, talk(client), asio::detached);
    ioc.run();
}
```

### Lifecycle

```
Disconnected --connect()--> Connecting --ok--> Connected --lost--> Reconnecting --ok--> Connected
                                |                  |                    |
                              fail               close()          attempts exhausted
                                |                  |                    |
                 Disconnected / Reconnecting     Closing -> Closed    Failed
```

* `connect()` resolves once the first connection is up, retrying according to
  `ReconnectPolicy`. After that the loop keeps reconnecting in the background.
* `send()` fails with `NotConnected` while the link is down; it never queues.
* `receive()` pulls from a bounded queue (`receive_queue_capacity`); when it is
  full the socket is no longer read (back-pressure). It fails with
  `ConnectionClosed` after `close()` or once the client gave up, after any
  buffered messages have been drained.
* `close()` sends a close frame, stops reconnecting and returns when everything
  has shut down. Destroying the client aborts all pending work.
* `on_state_change` / `on_error` callbacks are invoked on the `io_context` thread.

### Errors

Every operation returns `awc::Result<T>` (`std::expected<T, awc::Error>`).
`Error` carries an `ErrorCode`, a human readable message and the underlying
`boost::system::error_code` when there is one:

```
ConnectFailed: cannot connect to 127.0.0.1:9011 [system:111 Connection refused]
```

### Logging

The library logs through the spdlog logger named `awc`. Replace or configure it:

```cpp
awc::log::set(my_logger);                   // route into your own sinks
awc::log::set_level(spdlog::level::debug);  // state transitions, handshake details
awc::log::set_level(spdlog::level::trace);  // every message / ping / pong
```

### Threading

The client is not thread safe: call it from the thread running the
`io_context` (use `asio::dispatch`/`co_spawn` from other threads).

## Known defects

Found during an external review on 2026-10-10. Each one was reproduced with the
scenarios named below from wsbench, a separate test harness; none is covered by this
project's own tests.

### Heartbeat misses a dead peer while a send is stuck

The pong timeout only starts after `async_ping` has completed (`ping_loop` in
`src/client.cpp`). If the peer stops reading while a large `send()` is in flight, the
socket buffers fill up and Beast queues the ping behind the stuck write. The ping
never completes, so the pong timeout never starts and the client stays `Connected`
indefinitely. In the same situation, `close()` did not complete within 6 s.

- Reproduced by `Heartbeat.DetectsDeadPeerDuringStuckSend`: the peer stops reading,
  a 64 MiB send starts, and the first ping is due after 500 ms with a 100 ms pong timeout.
  The client was still connected 3 s later.
- Suggested fix: start the pong deadline when the ping is issued, not when its write
  completes. For example, run `async_ping` in its own coroutine and let the ping loop
  wait for the pong deadline independently.
- Related, documented limitation: while the receive queue is full (`reader_blocked_`),
  the pong timeout is skipped, so a dead peer also goes unnoticed while the application
  is not calling `receive()`.

### Use-after-free when the client is destroyed during `connect()` or `close()`

`WebSocketClient::connect()` and `close()` return member coroutines of
`detail::ClientImpl` that hold a raw `this`. Nothing keeps the `ClientImpl` alive for
the awaiting coroutine. When the client is destroyed while either call is pending,
`abort()` ends the connection loop, the loop's completion handler drops the last
`shared_ptr`, and the pending call then resumes on freed memory. This contradicts
"Destroying the client aborts all pending work" above.

- AddressSanitizer reports `heap-use-after-free` at `src/client.cpp:132` (the wait
  loop in `connect()`) and `src/client.cpp:208` (the wait loop in `close()`).
- Reproduced by `Shutdown.DestroyWhileConnecting`, `Shutdown.DestroyWhileWaitingToReconnect`,
  `Shutdown.DestroyWhileCloseIsPending`, `Basics.SendFailsPromptlyWhenNotConnected` and
  `Reconnect.BackoffDelayGrows`. These all destroy the client while `connect()` or
  `close()` is still pending. Without sanitizers they pass, because reading the freed
  memory happens not to crash.
- Suggested fix: have each facade method keep a `shared_ptr<ClientImpl>` in the
  coroutine frame until the operation completes, e.g.
  `[](auto impl) -> awaitable<Result<void>> { co_return co_await impl->connect(); }(impl_)`.

### Packaging

- **C++23 is not passed on to consumers.** The standard is set with
  `set(CMAKE_CXX_STANDARD 23)`, which only applies to targets in this project. A project
  that uses the library via `add_subdirectory` and does not set C++23 itself fails to
  compile `error.hpp` (`std::expected` is C++23). Fix:
  `target_compile_features(async_websocket_client PUBLIC cxx_std_23)`.
- **`find_package` does not work after install.** `install(EXPORT ...)` installs the
  targets file but no `async_websocket_clientConfig.cmake`, so
  `find_package(async_websocket_client)` fails. Fix: generate a config file (and a version
  file) with `CMakePackageConfigHelpers` and install it next to the targets file.
